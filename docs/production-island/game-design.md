# 生産の島 ゲーム仕様

2026-10-15 作成。ゲームの主軸「生産の島」の規則・数値・画面の流れと、Hack Day に作る写真判定の API の形をまとめる。**生産の島の値と規則はこの文書と `IslandParameters` を正とする。** 氷・盾・おかえり・来訪の規則は [`docs/game-logic.md`](../game-logic.md) のまま使う。

## 1. 骨格

2026-10-17 にオーナーがまとめた「ゲームのコア」を反映した (`docs/decisions.md`)。**お魚・インフラ・氷の 3 つが互いに効き合う。**

```
はじめまして → 島にはペンギンがいる。でも氷が溶けていっちゃってる…
  → エコだと思えば何でもいい。1 日 1 枚写真を撮ろう
  → インフラ (電気・ガス・水道) が手に入る → まずは氷室を建てよう → 氷が溶けにくくなる
  → 氷が大きいと、建てられる土地が増えるだけでなく、ペンギンのやる気が上がって施設の効果も上がる
```

```
毎日 1 枚のエコ写真 = 記録 ─▶ 氷 (game-logic.md の規則) = 島が支えられる土地の広さ ＋ ペンギンのやる気 (施設の効果)
       │                         ▲
       │                         └── 氷室: 記録しなかった日に溶ける量を減らす
       ├─▶ インフラ: 電気・水・ガス (それぞれにまつわるエコの写真、ガスは歩数でも)、オールマイティ (ミッションの振り返り)
       │
       └─▶ 施設を建てる (インフラ＋お魚) → ペンギンが働く (お魚を食べる) → 品物を作る → 港の注文に届ける → お魚 (通貨)
                                                                                                  │
            お魚の桁が上がる (100・1,000・1 万・10 万) ─▶ 新しい施設が開く ◀───────────────────────┘
放置すると氷が溶ける ─▶ 後から広げた土地から沈む ─▶ 上の施設が止まる (記録して氷が戻れば浮かぶ)
```

- **お魚**はゲーム内の通貨で、**減る**。建てる・強化する・広げるに使い、働くペンギンのごはんとして動かし続けるのにも使う (手本は「ねずだく」)。課金に使えるかは未決 (`docs/decisions.md`)。
- **インフラ** (電気・ガス・水道) は、それぞれにまつわるエコをしたときに多く手に入る (§4 の写真の表)。
- **ペンギン**は施設の働き手で、価値は数にある (記録を続けると増える。宿舎で住める数を増やす)。**種は実績** (アチーブメント) で解放し、数とは別に数える。普通のペンギンが 100 羽いて、珍しい種が 1 羽でもよい。図鑑のボーナスは残す (§7)。

- 手本は「ほしの島のにゃんこ」の「作る → 売る → 建てる → 島を広げる」の循環。にゃんこ = ペンギン、お客さんの注文 = 港の舟の注文、コイン = お魚。
- 記録の手段はレシートではなく **1 日 1 回のエコ写真** (何を撮ってもよい)。キャッシュレス化でレシートが出ない利用者が多いため (`docs/decisions.md`)。
- 物の流れは共有の在庫 (施設が作った品物は島の在庫に入り、別の施設がそこから使う)。Web 試作 `penguin-village` の「有向の線でつなぐ」方式は、インフラを引く操作が現実寄りすぎるため採らない。線と接続口の素材は残してある。

## 3. 盤面と土地

| 項目 | 値 |
|---|---|
| 大きさ | 10×10 マス (1 マス = 1m)。奥の 2 列は水路で、真ん中に港が浮かぶ |
| 基礎の島 | 中央 4×4 (x 3〜6, y 2〜5)。沈まない |
| 開拓 | 陸 (沈んでいない) に上下左右で接する海を凍らせる。水 `5 × 1.15^n`・お魚 `10 × 1.2^n` (n = 開拓済みの数、切り上げ)、経験値 +5 |
| 開拓の上限 | 氷が支えられる数 C と、レベルの上限 `4 + (レベル − 1) × 4` の小さい方。沈んでいるマスがある間は広げられない |
| 支えられる数 C | `floor((氷 − 40) / 2.5)`。氷 40 で 0、100 で 24、150 で 44 |
| 沈む | 開拓した数 N が C を超えたら、**後から開拓したマスから** N − C マス沈む。開拓の逆順なので、残る陸は必ず基礎の島とつながる |
| 沈んだマス | 上の施設は止まり (倉庫・宿舎・増幅所も効かない)、水に沈んだ見た目になる。C が戻れば浮かんで動き出す。消えない |
| 予告 | 次に沈む 3 マスにひびを出す (いちばん次は大きいひび) |
| 質の良いマス | 海に散らした豊漁 (1,3)(8,5)・塩の浜 (2,0)(7,0)・藻場 (1,6)(8,2)。開拓して対応する施設を建てると速さ ×1.5 |

## 4. 資源

| 資源 | 使い道 | 得かた |
|---|---|---|
| 電気 (インフラ) | 建てる・強化する | 写真 (電気の節約。写真の表は `resources.md`) |
| 水 (インフラ) | 開拓・氷室を建てる | 写真 (水の節約・マイボトルなど) |
| ガス (インフラ) | 施設を動かす (毎時消費) | 歩数 500 歩で 1 (1 日 20 まで)。写真 (ガスの節約: 鍋にふた・重ね着、短いシャワー、エコな移動) |
| オールマイティ | 電気・水・ガスのどれの代わりにもなる (足りない分を自動で使う) | ミッションの振り返り (できた +5、少しだけ・できなかった +2)、食べ物・物の写真 |
| お魚 | 通貨 兼 一次品目。建てる・強化・開拓・さばく、**働くペンギンのごはん** (施設ごとの毎時の量。漁場は 0)。持ったお魚の最大の桁で施設が開く | 漁場、港の注文 |
| 真珠 | 施設に入れると速さ +10% (1 施設 5 つまで) | 研究所 |

- 写真の資源は **1 日 1 枚まで**。記録 (氷) は 1 枚目で付く。判定できない写真でも電気・水・ガス +3 ずつは入る。
- 「1 日」は氷の状態機械が数える日 (時計を戻したときは最後に見た日)。最後に受け取った日より前の日の写真・歩数は資源にしない (時計を前後させて何度も受け取れないように)。
- 増幅所 (電気・水・ガス、各 2 棟まで) 1 棟で受け取る量 +25%。来たペンギンのボーナス (§7) と掛け合わせる。
- 初期値: 電気 30・水 20・ガス 30・お魚 30。

| 漁場 | 2×2 | 最初から | 10 | 0 | 1 | 0 | お魚 1 (4) | 0.25 | 海に面する |
| 倉庫 | 1×1 | 最初から | 5 | 20 | 0 | 0 | 置き場 +30 | — | |
| 宿舎 | 1×1 | 100 | 10 | 50 | 0 | 0 | 住めるペンギン +4 | — | |

| 電気の増幅所 | 2×2 | 1,000 | 30 | 80 | 0 | 20 | 電気 +25% | — | 2 棟まで |
| 海藻場 | 2×2 | 1,000 | 30 | 100 | 1 | 30 | 海藻 (8) | 0.25 | 海に面する |
| 水の増幅所 | 2×2 | 1,000 | 30 | 120 | 0 | 20 | 水 +25% | — | 2 棟まで |

| ちくわ工場 | 2×2 | 10,000 | 40 | 200 | 1 | 60 | すり身 2 → ちくわ (とろ火 10 / 強火 6) | 0.5 / 1.5 | |
| ガスの増幅所 | 2×2 | 10,000 | 30 | 150 | 0 | 40 | ガス +25% | — | 2 棟まで |
| 干物場 | 2×2 | 10,000 | 50 | 300 | 1 | 80 | お魚 2 + 塩 → 干物 (12) | 0.5 | |
| 研究所 | 2×2 | 10,000 | 60 | 400 | 1 | 100 | お魚 20 + 海藻 2 → 真珠 (60) | 0.5 | 1 棟まで |
| 仕分け所 | 1×1 | 100,000 | 40 | 500 | 1 | 150 | そろった注文を自動で納品 | — | 1 棟まで |
| おでん屋台 | 2×2 | 100,000 | 120 | 2000 | 2 | 400 | かまぼこ + ちくわ + 海藻 → おでん (20) | 1.0 | |

- **開くお魚**: これまでに持ったお魚の最大 (`IslandGame.MaxFishHeld`) がこの数に届くと建てられる。持っているお魚は減るので、一度開いた鍵は閉じない。開いたら「お魚 1,000 匹！」の知らせと棚の NEW で知らせる。段は `IslandCatalog.UnlockSteps`。2026-10-17 までの「解放 Lv」を置き換えた。レベル (経験値) は、開拓の上限と強化の上限として残る。
- **ごはん**: 動いている間、働くペンギンがお魚を食べる (`FacilityDef.FishPerHour`)。お魚が尽きると「ごはんのお魚が足りない」(`FacilityStatus.NoFish`) で止まり、増幅所・氷室も効かなくなる。漁場は自分でとった魚を食べるので 0 で、お魚 0 からでも立ち直れる。
- **氷室**: 効き目は `IceHouseReduction + (Lv − 1) × IceHouseReductionPerLevel` にやる気 (§6) を掛け、上限 0.8。氷の計算は `GameSession` にあるので、`GameStateSystem` が効き目の変化を操作 (`GameOp.MeltGuard`) として記録し、`GameSession.SetMeltReduction` に渡す (再生すれば同じ氷になる)。盾は先に使う。
- 港の注文の品目は、開いた施設が作れるものから選ぶ。
- 止まる理由: 沈んでいる・海に面していない・ペンギンが足りない・ガス切れ・ごはんのお魚が足りない・材料待ち・置き場がいっぱい。画面にアイコンで出す。
- 置き場の上限はお魚以外の品物 1 種類ごとに 20 + 倉庫 1 棟につき 30。お魚は上限なし。
- 取り壊すと建てたときの半分が戻る。移すのは無料。
- 建てると経験値 `5 + 開く段 × 3` (段はお魚の桁。最初から = 1、100 匹 = 3、1,000 匹 = 4 …)。

## 6. ペンギン (働き手・やる気・種)

- 住んでいるペンギンの数 = `min(住める数, 1 + 記録した日の数)`。看板のペンギン 1 羽から始まり、最初の写真で 2 羽になって氷室と漁場を動かせる (2026-10-17 に 3 から 1 にした)。住める数は 4 + 宿舎 1 棟につき 4。種とは関係なく数える。
- 島を歩くペンギンと小屋の氷山のペンギンは、全員足踏みのアニメーション付きのモデル (`Penguin_v001/Penguin_Waddle_1p3m.fbx`) にそろえ、足の動きがそろわないよう再生位置をずらす (`AnimatorPhaseOffset`)。立ち止まっている間はゆっくり足踏みする。組み込みは **Production Island > Setup Home Island**。
- 画面のペンギンの顔 (`.pp-icon--penguin`) は、看板のペンギン (`Penguin_v002`) の頭を 3D モデルから描き出した絵 (**Production Island > Render Mascot Icon**)。アプリのアイコンの下書き (1024px) も `ArtSource/Penguin_v002/` に出す。
- 建てると手のあいているペンギンが自動で配属される。施設のシートで増減できる。働き手が減ったら後から建てた施設から外す。
- **やる気**: 氷の段 (`GameSession.Tier`、ヒステリシス込み) で決まる。T0〜T2 ×1.0、T3 (ゆたか) ×1.15、T4 (ひろがる) ×1.3 (`IslandParameters.MotivationByTier`)。作る速さ・増幅所の上乗せ・氷室の効き目に掛かる。罰にしないため 1.0 より下げない。ホームの氷のカードに「やる気×1.15」を添える。
- **種は実績で解放する** (`PenguinUnlocks`、19 種すべてに条件)。記録の節目の 7 種 (アデリー・コビト・ガラパゴス・ヒゲ・オウサマ・コウテイ・キンメ) は `GameSession` の条件のまま (週 1 種まで。game-logic.md §5)。週の順で来ていた 11 種とマゼランは、島の実績 (港に 10 回届ける、お魚 1,000 匹、島を 10 マス広げる、施設 6 種類、港 3 段目、かまぼこ・ちくわ・干物を 10 個、真珠、おでん、氷室 Lv5、写真を 3 つの分類で撮る) を満たした時点で来る。そのためアプリは `GameParameters.App` (`WeeklyArrivals = false`) で週の来訪を止める。図鑑は、まだの種に条件と進み具合 (3 / 10) を出す。
- ペンギン以外の動物 (シロクマなど) を解放できるようにするかは未決。

## 7. 図鑑のボーナス

19 種それぞれが 1 つのボーナスを持つ (`PenguinDex`。2026-10-17 のコアの整理で「ペンギン自体に価値はない (仮)」とされたが、オーナーの判断で残す)。例: アデリー → 漁場の速さ +10%、コウテイ → ガスを受け取る量 +20% (2026-09-29 のボードの「皇帝ペンギン：ガスの生産量が 1.2 倍」)、キガシラ → 港の報酬 +10%。事実の一行は実在のペンギンの話で、アプリの氷とは関係ない。

## 8. 港・レベル

| 項目 | 値 |
|---|---|
| 注文 | 3 件。品目は今のレベルで作れるものから、新しい品目ほど出やすく選ぶ (決まった順の乱数) |
| 個数 | `round((10 + レベル × 4 + 0〜5) / 品目の値)` (1 以上) |
| 報酬 | お魚 `品目の値 × 個数 × 1.5 × ペンギンの倍率`、経験値 `品目の値 × 個数 × 0.5 + 2` |
| 品目の値 | お魚 1・すり身 5・塩 3・海藻 3・かまぼこ 15・ちくわ 15・干物 12・おでん 80 |
| 次の舟 | 納品から 45 秒後 |
| 港の段階 | 納品の累計 1・5・12・25・45 回で 6 段階 (予定地 → おでん祭り) |
| レベル | n → n+1 に経験値 `20 × n^1.5` (切り上げ)。最大 30。開拓できるマス数と、施設を強化できるレベルの上限を決める (施設が開くのはお魚の桁) |

## 9. 時間

- 島は実時間で動く。アプリを閉じていた間は、開いたときにまとめて計算する (上限 12 時間)。60 秒以上あいていれば「おかえり」で作ったものを見せる (これがおかえりのごほうび。氷のおかえりは 2026-10-16 にやめた。`resources.md`)。
- 時刻は引数で受け取り (`IslandGame.Tick(now)`)、Domain は `DateTime.Now` を読まない。時計が戻っていれば何もしない。
- 長い留守は刻みを粗くするが、1 回の刻みで何回でも作り終えられるので、量は 1 秒刻みと同じになる (テストで確かめている)。

## 10. 保存

- 端末の `Application.persistentDataPath/penguin.db` (SQLite、`SqliteGameStore`)。meta・ops (氷への操作、追記だけ)・island (島の JSON)・activity (受け取りの記録、追記だけ。全件を残し、画面には新しい 200 件) の 4 表。1 トランザクション (WAL) で書くので、途中で落ちても前の状態が残る。初期の `penguin-save.json` があれば最初の起動で取り込み、`.imported` に改名して残す (`JsonGameStore`・`SaveStore` はその読み取りに使う)。写真と購買の明細は入れない。
- 氷の状態機械は **操作の記録 (時刻・種類・引数) を保存し、起動時に時計を止めて再生する** (`GameStateSystem.Replay`)。計算が決定的なので同じ状態に戻る。`GameSession` は変えていない (Python の参照実装と一致させているため)。
- 島は状態をそのまま保存する (`IslandSave`)。
- 写真そのものは保存しない。記録画面に残すのは分類・写っていたものの名前・受け取った資源の量だけ。
- 島の保存 (`IslandSave`) は版 2 (2026-10-17): これまでに持ったお魚の最大・ごはんの端数・作った品目の数・撮った分類・実績で来た種を足した。版 1 の保存は、持っているお魚と建てた施設が開いている所までを解放済みとして読む。
- 操作の記録 (ops) に「氷室の効き目」(`meltguard`、数値は `value` 列) が加わった。

## 11. 画面の流れ

| 画面 | 内容 |
|---|---|

## 12. 写真判定の API (Hack Day に作る)

クライアントは `IEcoPhotoJudge.JudgeAsync(byte[] jpeg)` だけを呼ぶ。Hack Day に `HttpEcoPhotoJudge` を足して `EcoPhotoFlowPresenter.SetJudge` で差し替える。

```
POST /v1/eco-photo/judge
Content-Type: multipart/form-data   (image: JPEG、長い辺 1280px まで)

200 OK
{
  "subject": "my_bottle",        // 写真の表の ID (resources.md の「写真の表」)。どれでもなければ "unknown"
  "comment": "マイボトル、かっこいいね",  // ペンギンのひとこと (40 文字まで、数字を言わない)
  "confidence": 0.82
}
```

- `subject` は `EcoSubjects.FindById` で引く。知らない ID と `"unknown"` は「判定できない写真」(電気・水・ガス +3 ずつ) にする。名前とカテゴリは表から決まるので、サーバーは返さない。

- サーバーは画像をメモリ上で Gemini に渡し、応答を Pydantic で検証してから返す。画像も応答もディスク・ログに残さない (`.claude/rules/privacy.md`)。アプリとサーバーは保存しないが、**Gemini API 側での入力の保持は Google の利用規約に従う** (`docs/privacy-policy.md`)。
- `subject` の ID は `resources.md` の写真の表と同じ (2026-10-17 に `lid_cooking`・`warm_clothes` を足した)。
- 資源の量はサーバーでは決めない。クライアントが写真の表 (`EcoSubjects`) から決める。不正に強くする必要が出たら、そのときにサーバーへ移す。
- 失敗 (通信・判定不能) のときは 4xx/5xx を返し、クライアントは「もう一度撮ってね」を出してスキャン画面に戻る。

数値は `IslandParameters` と `IslandCatalog` にまとめてある。変えたら `IslandGameTests` (特に 8 週の通しの模擬テスト) を回す。
