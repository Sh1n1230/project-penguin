# データ取り扱いルール

このプロジェクトが扱うのは**ユーザーの購買履歴そのもの**。以下は実装後に足す対策ではなく、書き始める前の制約として扱う。

## レシート画像

- **ディスクに書かない。** メモリ上で処理し、Gemini へのリクエスト完了後に破棄する。一時ファイル・アップロードディレクトリ・キャッシュディレクトリを作らない。`tempfile` や `UploadFile.file` のディスク退避に注意する。
- **ログに出さない。** 画像バイト列はもちろん、そこから抽出した店名・品目・金額もログに残さない。例外ハンドラのスタックトレースやリクエストダンプに混入させない。
- **エラーレスポンスに含めない。** バリデーション失敗時も、入力の中身をそのまま返さない。

## 端末外に出してよいもの

算出済みの **CO₂e 値と、それに必要な最小限のメタ情報だけ**。購買明細の生データをサーバ側に集約・保存・永続化しない。DB テーブルやキャッシュを設計するときも同じ。

## API キー

- 環境変数からのみ読む。コードへのハードコード、設定ファイルへの実値記入、テストフィクスチャへの埋め込みをすべて禁止する。
- **Unity クライアントに一切渡さない。** ビルド成果物を展開すれば取り出せてしまうため、クライアント側の固定シークレットは対策にならない。
- 実キーを `.env.example` に書かない。プレースホルダのみ。

## テストデータ

- **実物のレシート画像をリポジトリに置かない。** `tests/` のフィクスチャは合成画像か、画像を使わないモックに限る。
- SQLite ファイル (`*.db` / `*.sqlite*`) はコミットしない (`.gitignore` 済み)。

## 認証

エンドポイント認証は現時点で未実装。クライアントへの固定シークレット埋め込みは対策にならないため、実装するなら Firebase Auth 等の正規のユーザー認証を提案すること。安易な API キーヘッダ方式を実装しない。
